# 02 — Лента постов на jQuery

> Вторая ступень «эволюции фронтенда». Приложение то же, что в `01-vanilla-js`, но код переписан на **jQuery**, библиотеке, которая примерно с 2006 по 2015 год была фактическим стандартом веб-разработки.

---

## Что делает приложение

Функции те же, что в первой версии:

- добавить пост (заголовок + текст);
- лайкнуть пост (счётчик +1);
- удалить пост (с подтверждением через `confirm`);
- когда постов нет, показать сообщение «Постов пока нет».

Функционально ничего не поменялось, отличается только **способ написания кода**. Так удобнее всего сравнивать технологии между собой.

---

## Как запустить

1. Откройте файл `index.html` в браузере (двойной клик).
2. Нужен интернет: jQuery подключается с CDN (`code.jquery.com`).
3. Подзаголовок теперь **синий**, это фирменный цвет jQuery. По нему видно, что открыта вторая версия.

Сборщики, Node.js и `npm install` не нужны.

## Зачем вообще появился jQuery

В середине 2000-х браузеры (Internet Explorer 6/7/8, Firefox, Opera, Safari) очень по-разному понимали JavaScript:

- в IE события вешались через `attachEvent`, в остальных браузерах через `addEventListener`;
- `querySelector` ещё не было: элементы искали через `getElementById` / `getElementsByTagName` и вручную фильтровали;
- AJAX в IE требовал `new ActiveXObject(...)`, а в остальных браузерах `new XMLHttpRequest()`.

jQuery (Джон Резиг, 2006) спрятал эти различия за одним коротким API. Девиз библиотеки: **«Write less, do more»** («пиши меньше, делай больше»).

Позже браузеры договорились о стандартах, и многое из jQuery вошло в сам JavaScript: `querySelector`, `classList`, `fetch`, `closest`. Поэтому в новых проектах jQuery сегодня почти не используют. Но он **до сих пор работает на огромном количестве сайтов** (WordPress, старые корпоративные системы), и его стоит уметь читать.

## Ключевые отличия от версии 01 (Vanilla JS)

| Задача | Vanilla JS (v1) | jQuery (v2) |
|---|---|---|
| Ждать загрузки DOM | скрипт подключён в конце `<body>` (или `DOMContentLoaded`) | `$(function () { ... })` |
| Найти элемент | `document.getElementById('post-form')` | `$('#post-form')` |
| Повесить обработчик | `el.addEventListener('submit', fn)` | `$el.on('submit', fn)` |
| Значение поля | `input.value` | `$input.val()` |
| Показать/скрыть | `if/else` + `classList.add/remove('hidden')` | одна строка `$el.toggleClass('hidden', cond)` |
| Создать карточку поста | много `document.createElement` + `appendChild` | одна HTML-строка (шаблонная строка) + `.prepend()` |
| Клики по кнопкам постов | отдельный `addEventListener` на **каждой** кнопке | **делегирование**: `$container.on('click', '.btn-like', fn)`, один обработчик на всех |
| Узнать, какой пост кликнули | `id` передаётся в замыкании: `() => handleLike(post.id)` | `$(this).closest('.post-card').data('id')` |
| data-атрибут | `el.dataset.id` (всегда строка) | `$el.data('id')` (сам приводит `"5"` к числу `5`) |
| Изменить текст | `el.textContent = '...'` | `$el.text('...')` |
| Защита от XSS | `textContent` вставляет текст безопасно | в HTML-строке нужно экранировать: `$('<div>').text(str).html()` |

### Что важно понять «под капотом»

**`$` — это просто функция.** Её имя состоит из одного символа `$`. Вызов `$('#post-form')` возвращает не DOM-элемент, а **jQuery-объект**, то есть «обёртку» над массивом найденных элементов. Поэтому:

- у jQuery-объекта нет `.value` или `.reset()`, есть только методы jQuery (`.val()` и т. д.);
- до «настоящего» DOM-элемента можно добраться через индекс: `$form[0].reset()`;
- методы работают **сразу со всеми** найденными элементами: `$('.post-card').addClass('x')` добавит класс каждому посту без цикла.

**Цепочки вызовов (chaining).** Большинство методов возвращают тот же jQuery-объект, поэтому вызовы можно писать подряд:

```js
$('.post-card').addClass('liked').find('.btn-like').text('❤️ 5');
```

**Префикс `$` у переменных** (`$postForm`, `$postsContainer`) — просто договорённость между программистами. Он подсказывает, что в переменной лежит jQuery-объект, а не обычный DOM-элемент.

**Делегирование** в jQuery встроено прямо в метод `.on()`: третьим аргументом передаётся селектор. Обработчик висит на контейнере, а jQuery сам проверяет, по какому элементу кликнули. Поэтому обработчик работает и для постов, добавленных позже.

## Подход остаётся тем же: «императивный»

jQuery сокращает код, но **мышление не меняется**. Мы по-прежнему сами решаем, *как* и *когда* обновлять DOM:

1. изменили массив `posts`;
2. вручную перерисовали список или поменяли текст счётчика.

Если забыть второй шаг, данные и экран **рассинхронизируются**. Это главная проблема императивного подхода. Она решается в следующих версиях:

- **03-oop** — раскладываем код по классам (данные / отображение / управление), чтобы он не превращался в «спагетти»;
- **04-vue** и **05-react** — переходим к *декларативному* подходу: описываем, *как должен выглядеть* экран при текущих данных, а фреймворк сам обновляет DOM.

## Практические задания

1. **Счётчик постов.** Выведите над лентой текст «Всего постов: N» и обновляйте его при добавлении и удалении.
2. **Анимация удаления.** Вместо мгновенного `.remove()` используйте `.fadeOut(300, function () { $(this).remove(); })`. В Vanilla JS для этого пришлось бы писать CSS-переход и слушать `transitionend`: почувствуйте разницу.
3. **Цепочка.** Перепишите обработчик лайка так, чтобы он стал одной цепочкой вызовов jQuery.
4. **Сравнение.** Откройте `01-vanilla-js/main.js` и `02-jquery/main.js` рядом. Найдите 3 места, где jQuery сократил код, и 1 место, где он ничего не дал.
5. **Без jQuery.** Посмотрите сайт [youmightnotneedjquery.com](https://youmightnotneedjquery.com/): там показано, как каждый метод jQuery пишется на современном JS.
