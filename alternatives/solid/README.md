# 🟦 Альтернатива: SolidJS — сигналы вместо перерисовок

> **Лента постов** на [SolidJS](https://www.solidjs.com/): синтаксис почти как у React (JSX, функции-компоненты),
> но внутри — совершенно другая модель. Компонент выполняется **один раз**, виртуального DOM нет,
> а изменения доставляются точечно — прямо в нужный текстовый узел.

Цвет версии: **`#2c4f7c`** (фирменный синий Solid).

---

## 📍 Где эта версия на карте проекта

Помнишь главный вопрос из обсуждения: **«как экран узнаёт, что данные изменились?»**

| Версия | Ответ | Что перезапускается при лайке |
|---|---|---|
| 01 Vanilla | вызываем `render()` руками | весь список (innerHTML) |
| 03 OOP | store кричит `emit('change')` | весь список |
| 05 React | новая копия массива → React сравнивает виртуальные DOM | компонент + дети |
| 05b MobX | `observer()` следит, что компонент прочитал | одна карточка |
| 04 Vue | Proxy + виртуальный DOM | одна карточка (шаблон) |
| **Solid** | **сигналы + компилятор** | **один текстовый узел «❤️ 2»** |

Solid — это логическое завершение идеи «точечной реактивности», которую мы видели во Vue и MobX,
только **без виртуального DOM** вообще. Эта же идея («сигналы») сейчас приходит в Angular (см. `alternatives/angular`),
Vue Vapor, Preact Signals, Svelte 5 (`$state`) и даже обсуждается как стандарт JavaScript (TC39 Signals).

## 🧠 Главная идея: компонент — это setup, а не render

В React функция-компонент — это **render**: она вызывается при каждом изменении,
и React сравнивает новый результат со старым.

В Solid функция-компонент — это **setup**: она вызывается **один раз**, создаёт DOM-узлы
и «развешивает» подписки. После этого функция больше не нужна.

```jsx
function Counter() {
  const [count, setCount] = createSignal(0);
  console.log('выполнено');        // React: при каждом клике. Solid: ОДИН раз.
  return <button onClick={() => setCount(count() + 1)}>{count()}</button>;
}
```

Компилятор превращает `{count()}` примерно в такое:

```js
const button = document.createElement('button');
const text = document.createTextNode('');
button.append(text);
createEffect(() => { text.data = count(); });   // ← подписка ТОЛЬКО на этот узел
```

То есть JSX в Solid — это не «описание виртуального дерева», а **инструкция компилятору**,
какие DOM-операции сгенерировать.

### Проверь сам

В `PostCard.jsx` стоит `console.log`. Добавь два поста и нажми «лайк» 10 раз.
В консоли будет ровно **две** строки — по одной на создание каждой карточки.
В React (v05) лог срабатывал бы при каждом клике.

## 🔧 Примитивы Solid

### `createSignal` — одно реактивное значение

```js
const [title, setTitle] = createSignal('');
title();          // читаем — ВЫЗОВ функции (и подписка, если мы внутри JSX/эффекта)
setTitle('abc');  // пишем
```

**Самое важное отличие от `useState`:** `title` — это функция-геттер, а не значение.
Именно момент вызова `title()` Solid использует, чтобы понять, кто от чего зависит.

### `createStore` — реактивный объект или массив

```js
const [posts, setPosts] = createStore([]);
setPosts((p) => p.id === id, 'likes', (l) => l + 1);   // «путь» до поля
```

Store построен на Proxy (как Vue 3 и MobX): каждое поле каждого поста отслеживается отдельно.
Читаем как обычный объект (`posts[0].likes`), но **меняем только через `setPosts`** —
это компромисс между «меняй напрямую» (MobX/Vue) и «не меняй, создавай копию» (React/Redux).

Если хочется мутабельного стиля — есть `produce` (как Immer):

```js
setPosts(produce((draft) => { draft.splice(index, 1); }));
```

### `createMemo` — вычисляемое значение

```js
const totalLikes = createMemo(() => posts.reduce((s, p) => s + p.likes, 0));
```

Аналоги: `computed` во Vue, `get` в MobX, `useMemo` в React (но без массива зависимостей —
Solid сам видит, что прочитано).

### `createEffect` — побочный эффект

```js
createEffect(() => { document.title = `(${postsCount()}) Лента`; });
```

Аналог `useEffect`, но **без массива зависимостей**: эффект перезапустится, когда изменится
любой сигнал, прочитанный внутри. Не нужно ничего перечислять — и нельзя ошибиться.

### `createRoot`

Сигналы и memo можно создавать вне компонентов (как мы делаем в `store.js`).
`createRoot` даёт им «владельца», чтобы Solid знал, когда их можно уничтожить.

## 🧩 Управляющие компоненты: `<Show>` и `<For>`

Поскольку компонент выполняется один раз, обычный `array.map()` выполнился бы тоже один раз.
Поэтому для условий и списков есть специальные компоненты:

```jsx
<Show when={posts.length > 0} fallback={<Empty />}>
  <ul>
    <For each={posts}>{(post) => <PostCard post={post} />}</For>
  </ul>
</Show>
```

- `<Show>` — условный рендер, `fallback` — что показать иначе (наш empty state).
- `<For>` — отслеживает элементы **по ссылке**: при добавлении поста создаётся одна новая карточка,
  остальные DOM-узлы не трогаются. Поэтому `key` не нужен.
- Есть ещё `<Switch>/<Match>`, `<Index>`, `<Dynamic>`, `<Portal>`, `<ErrorBoundary>`, `<Suspense>`.

## ⚠️ Ловушки для тех, кто пришёл из React

### 1. Нельзя деструктурировать props

```jsx
// ❌ Значение «застынет» — лайки на экране перестанут обновляться
function PostCard({ post }) { const likes = post.likes; return <b>{likes}</b>; }

// ✅ Читаем внутри JSX — каждое чтение реактивно
function PostCard(props) { return <b>{props.post.likes}</b>; }
```

`props` в Solid — это реактивный объект-геттер. Деструктуризация читает поле один раз
в момент setup — и больше никогда. Для слияния/разделения props есть `mergeProps` и `splitProps`.

### 2. Сигнал — это функция

`{title}` выведет текст функции, `{title()}` — значение. Самая частая опечатка.

### 3. Ранний `return` не работает как в React

```jsx
// ❌ Компонент выполнится один раз; если сначала постов нет — так и останется пусто
if (posts.length === 0) return <Empty />;

// ✅
return <Show when={posts.length} fallback={<Empty />}>...</Show>;
```

### 4. `onInput`, `class`, `classList`

- События — нативные DOM-события: `onInput` срабатывает на каждый символ (в React это «переименованный» `onChange`).
- `class` вместо `className`, а для условных классов — `classList={{ invalid: hasError() }}`.

## 🔁 Сравнение с другими версиями: один и тот же лайк

```js
// v01 Vanilla
posts[i].likes++; render();

// v05 React (useReducer)
dispatch({ type: 'LIKE', id });   // reducer вернёт новый массив → перерендер

// v05a Redux
this.props.likePost(id);          // action → reducer → новый state → connect → перерендер

// v05b MobX
postStore.likePost(id);           // post.likes++ → observer перерисует карточку

// Solid
postStore.likePost(id);           // setPosts(..., 'likes', l => l + 1) → обновится текст «❤️ N»
```

| | React | MobX | Vue 3 | **Solid** |
|---|---|---|---|---|
| Синтаксис | JSX | JSX (React) | шаблоны / SFC | **JSX** |
| Модель | перерендер + VDOM diff | observable + перерендер компонента | Proxy + VDOM | **сигналы, без VDOM** |
| Компонент вызывается | на каждое изменение | на изменение прочитанного | шаблон — на изменение | **один раз** |
| Массивы зависимостей | да (`useEffect`, `useMemo`) | нет | нет | **нет** |
| Глобальный стор | отдельная библиотека | MobX | Pinia | **встроен (`createStore`)** |
| Размер рантайма (gzip, примерно) | ~45 КБ+ | +~20 КБ | ~30 КБ | **~7 КБ** |
| Экосистема | огромная | средняя | большая | **небольшая** |

## 👍 Плюсы и 👎 минусы

**Плюсы**
- Очень быстро: в бенчмарках (js-framework-benchmark) Solid стабильно рядом с чистым JS.
- Маленький размер, мало «магии» в рантайме — основная работа сделана компилятором.
- Нет массивов зависимостей, `useCallback`, `React.memo` — целый класс ошибок исчезает.
- Глобальное состояние без дополнительных библиотек.
- SolidStart — мета-фреймворк (аналог Next.js) с серверными функциями.

**Минусы**
- Экосистема и рынок вакансий заметно меньше, чем у React/Vue/Angular.
- «Похоже на React» — это одновременно и плюс, и ловушка: привычки (деструктуризация, ранний return) ломают реактивность.
- Меньше готовых UI-библиотек и обучающих материалов.

## 🏋️ Практические задания

1. **Увидеть разницу.** Скопируй `console.log` из `PostCard` в `PostCard` версии v05 (React). Сравни количество логов при 10 лайках.
2. **Сломать реактивность.** В `PostCard.jsx` замени `props` на деструктуризацию `{ post }` и вынеси `const likes = post.likes`. Убедись, что счётчик перестал обновляться. Верни как было и объясни своими словами, почему.
3. **Эффект без зависимостей.** В `App.jsx` добавь `createEffect(() => document.title = ...)` с количеством постов. Обрати внимание: массив зависимостей не нужен.
4. **Сохранение в localStorage.** В `store.js` загрузи посты из `localStorage` при старте и сохраняй их в `createEffect` (подсказка: `JSON.stringify(posts)` читает все поля — значит, эффект подпишется на всё).
5. **Сортировка.** Добавь сигнал `sortBy` (`'new' | 'likes'`) и `createMemo` с отсортированной копией. Переключатель — две кнопки. Сравни с Zustand из v06.
6. **`<Switch>/<Match>`.** Перепиши блок кнопок в `PostCard` с `<Show>` на `<Switch>`, добавив третье состояние «удаляется…» (имитация задержки `setTimeout`).
7. **`createResource`.** Сделай фейковый API (как `postsApi.ts` в v06) и загрузи посты через `createResource`. Покажи «Загрузка…» через `<Suspense>`. Сравни с TanStack Query.
8. **Счётчик символов.** Под textarea выведи «`body().length` / 500». Проверь в DevTools → Elements (подсветка изменений), что при наборе обновляется только этот текст.
9. **Чистый сигнал без компонентов.** В консоли браузера (в dev-режиме) импортируй `createSignal`, `createEffect`, `createRoot` и поиграй с ними без JSX — убедись, что реактивность не привязана к UI.

## 🎯 Ключевые мысли

- **Сигнал** = значение + список подписчиков. Чтение подписывает, запись уведомляет.
- **Компонент выполняется один раз** — он лишь строит DOM и связывает его с сигналами.
- **Виртуальный DOM не обязателен**: если точно знать, что от чего зависит, сравнивать деревья не нужно.
- Это та же идея, что и Observer из v03 (`store.on('change', ...)`), только автоматическая и сверхточная:
  подписка оформляется не на «весь store», а на одно поле одного объекта.

> Круг замкнулся: в v03 мы руками писали `EventEmitter` и подписки. Solid делает то же самое —
> но автоматически, на уровне каждого отдельного значения.
