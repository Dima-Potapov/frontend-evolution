# 05 — Лента постов на React (хуки)

> Пятая ступень «эволюции фронтенда». То же приложение, что в `04-vue`, но на **React 19 + Vite**. Компоненты — функции, состояние — хуки (`useState`, `useReducer`, `useRef`, `useEffect`, `useMemo`, `useCallback`), стили — CSS Modules.

---

## Что делает приложение

Функции прежние: добавить пост (с проверкой пустых полей), лайкнуть, удалить с `confirm`, показать заглушку, когда постов нет. Как и в v4, над списком есть строка статистики («Постов: N · Лайков всего: M»). Новое: количество постов отображается в заголовке вкладки браузера, это пример `useEffect`. Подзаголовок **бирюзово-синий** `#087ea4`, фирменный цвет сайта react.dev.

## Немного истории

React создал **Джордан Уолк** в Facebook, в 2013 году его открыли публично. Тогда идея казалась дикой: «HTML внутри JavaScript (JSX) и перерисовка всего интерфейса при каждом изменении». Секрет был в **Virtual DOM**: React перерисовывает лёгкое JS-описание интерфейса, сравнивает его со старым и вносит в настоящий DOM только разницу.

Ключевые вехи: 2015 — React Native (тот же React для мобильных приложений), **2019 — хуки** (React 16.8). До хуков состояние было только у классовых компонентов с `this.state`, `this.setState` и вечными `.bind(this)`, теми самыми из `03-oop/js/App.js`. В 2024 году вышел React 19, а следом React Compiler.

Vue (2014) появился как «более простая альтернатива Angular» и многое взял у React (Virtual DOM, компоненты). В свою очередь, Composition API во Vue 3 (2020) был вдохновлён хуками React. Технологии постоянно заимствуют идеи друг у друга.

## Главное идейное различие Vue и React

Если запомнить из этой версии только одно, пусть это будет эта таблица.

| | Vue (v4) | React (v5) |
|---|---|---|
| Как узнаёт об изменениях | **Следит** за данными через Proxy | **Не следит**: ждёт явного `setState` / `dispatch` |
| Как меняем данные | Мутируем: `post.likes++`, `posts.value.unshift()` | Создаём новое: `{ ...post, likes: post.likes + 1 }`, `[newPost, ...posts]` |
| Сколько раз выполняется код компонента | `<script setup>` — **один раз** | Тело функции — **при каждом рендере** |
| Что перерисовывается | Ровно то, что зависит от изменённых данных | Компонент и все его дети (если не помогать `memo`) |
| Кеш вычислений | `computed()` — зависимости находятся сами | `useMemo(fn, [deps])` — зависимости перечисляем руками |
| Шаблон | `<template>` + директивы (`v-if`, `v-for`, `v-model`) | JSX — обычный JavaScript (`&&`, `map`, `value`+`onChange`) |

Отсюда самая частая ошибка новичка в React: `posts.push(newPost); setPosts(posts);` — экран не обновится. Ссылка на массив та же, и React считает, что ничего не изменилось.

## Под капотом: что происходит при клике «❤️»

```
клик → onClick → likePost(id) → dispatch({ type: 'liked', id })
     → React планирует ре-рендер
     → postsReducer(старые посты, действие) → НОВЫЙ массив (лайкнутый пост — новый объект)
     → функция App() вызывается заново → новый JSX (Virtual DOM)
     → PostList() вызывается заново
     → PostCard обёрнут в memo: у нелайкнутых props те же → их рендер пропускается
     → сравнение старого и нового Virtual DOM (reconciliation)
     → в настоящем DOM меняется одна цифра и класс кнопки
```

Сравните с v3: там `store.like()` → `emit('change')` → `PostView.render()` → `replaceChildren` **всего** списка.

## Хуки этой версии: где искать

| Хук | Файл | Зачем | Аналог во Vue (v4) |
|---|---|---|---|
| `useState` | `PostForm.jsx` | значения полей и текст ошибки | `ref('')` |
| `useReducer` | `hooks/usePosts.js` | все правила изменения постов в одном месте | — (мутации в composable) |
| `useRef` | `hooks/usePosts.js` | счётчик id, который не вызывает ре-рендер | обычная `let` в setup |
| `useMemo` | `hooks/usePosts.js` | кеш суммы лайков | `computed()` |
| `useCallback` | `hooks/usePosts.js` | стабильные функции для `memo` | не нужен |
| `useEffect` | `App.jsx` | заголовок вкладки (побочный эффект) | `watch` / `watchEffect` |
| `memo` | `PostCard.jsx` | пропуск лишних рендеров карточек | не нужен (точечная реактивность) |

**Правила хуков:** вызывать только на верхнем уровне компонента или своего хука, никогда внутри `if`, циклов и колбэков. React различает хуки по **порядку вызова**.

## Сравнение всех версий

| Аспект | v1 Vanilla | v2 jQuery | v3 ООП | v4 Vue | v5 React |
|---|---|---|---|---|---|
| Подход | императивный | императивный | императивный + MVC | декларативный | декларативный |
| Разметка | в `index.html` | в `index.html` | в `index.html` + `createElement` | `<template>` в `.vue` | JSX в `.jsx` |
| Состояние | `let posts` | `let posts` | `#posts` в классе | `ref([])` | `useReducer` |
| Изменение данных | мутация | мутация | мутация + `emit` | мутация (Proxy видит) | **новый объект** |
| Обновление экрана | `render()` вручную | `render()` вручную | `render()` по событию | автоматически, точечно | автоматически, через ре-рендер + diff |
| Связь ребёнок → родитель | — | — | `onLike(handler)` | `emit('like', id)` | колбэк в props `onLike(id)` |
| Изоляция стилей | нет | нет | нет | `<style scoped>` | CSS Modules |
| Сборка | не нужна | не нужна | не нужна (нужен сервер) | Vite | Vite |

Интересно, что React в чём-то ближе к v3, чем к Vue: связь «ребёнок → родитель» в нём — это просто колбэк в параметрах (`onLike`), как `postView.onLike(handler)` из ООП-версии.

## Чего не хватает (и что будет в v6)

1. **Нет типов.** Можно передать `post={42}` или опечататься в `onLkie`, и узнаешь об этом только в браузере. Решение: **TypeScript**.
2. **Prop drilling.** `onLike` и `onRemove` идут через `PostList` транзитом. На трёх уровнях это терпимо, на семи уже больно. Решение: глобальный стор **Zustand**, где компонент сам берёт нужное.
3. **Нет сервера.** Посты живут в памяти и пропадают после перезагрузки. Загрузка, кеширование, состояния «загружается / ошибка» — это работа **TanStack Query**.
