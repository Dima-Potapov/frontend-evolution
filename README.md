# Frontend Evolution — одно приложение, 15 способов его написать

Учебный репозиторий: **одна и та же «лента постов»** (добавить пост, лайкнуть, удалить) написана снова и снова — от чистого JavaScript 2005 года до Next.js с базой данных и входом через Google.

Задача не в том, чтобы выучить 15 фреймворков. Задача — **увидеть, какую проблему решал каждый следующий шаг**. Функциональность одна и та же, поэтому всё, что меняется от версии к версии, — это и есть суть инструмента.

## Как проходить: пошагово

### 0. Подготовка (один раз)

1. Установи **[Node.js 22 LTS](https://nodejs.org/)** (нужен для версий 4+; Angular 21 требует Node ≥ 20.19).
2. Установи **[VS Code](https://code.visualstudio.com/)** и расширения:
   - **Live Server** (Ritwick Dey) — для версий 1–3a;
   - **Vue - Official** — для версий 4/4a;
   - **Prisma** — для версий 8–9;
   - **Angular Language Service** — для `alternatives/angular`.
3. Склонируй репозиторий:
   ```bash
   git clone https://github.com/Dima-Potapov/frontend-evolution.git
   cd frontend-evolution
   code .
   ```

### 1. Каждая папка — отдельный проект

В корне нет общего `package.json`. Для каждой версии с `package.json` открывай терминал **внутри её папки**:

```bash
cd 05-react
npm install      # один раз для этой папки
npm run dev      # откроется http://localhost:5173
```

Удобно: в VS Code правый клик по папке → **Open in Integrated Terminal**.

> ⚠️ **Версии 3 и 3a нельзя открыть двойным кликом** по `index.html`: ES-модули (`<script type="module">`) браузер не загружает с адреса `file://`. Правый клик по `index.html` → **Open with Live Server**. Или из папки: `npx serve .`

### 2. Ритуал на каждую версию (≈ 1–3 вечера на версию)

1. **Запусти** и потыкай приложение — убедись, что оно работает так же, как предыдущее.
2. **Прочитай README** этой папки — там объяснение, схема и сравнение с прошлой версией.
3. **Прочитай код** в порядке, указанном в README (обычно от точки входа к компонентам).
4. **Сравни с предыдущей версией** (см. ниже) — это самый полезный шаг.
5. **Ответь на 4 вопроса** (см. ниже) своими словами, письменно.
6. **Сделай задания** из раздела «Задания для практики» в README.
7. Только потом переходи дальше.

### 3. Сравнивай версии между собой

- VS Code: выдели два файла в проводнике (Ctrl+клик) → правый клик → **Compare Selected**. Например, `01-vanilla-js/main.js` и `02-jquery/main.js`.
- Или в терминале:
  ```bash
  git diff --no-index 07-nextjs/app/actions/posts.ts 08-nextjs-prisma/app/actions/posts.ts
  ```

Хорошие пары для сравнения: `01↔02`, `02↔03`, `04↔05`, `05↔05a`, `05↔06`, `06↔07`, `07↔08`, `08↔09`, `04↔alternatives/solid`.

### 4. Экспериментируй в своей ветке

Ломать код — нормально и полезно. Чтобы не бояться:

```bash
git checkout -b my-practice   # своя ветка для экспериментов
# ...правишь, ломаешь, делаешь задания...
git add . && git commit -m "v05: задание 3"
git checkout main             # вернуться к чистой версии в любой момент
```

Если хочешь хранить свои решения на GitHub — сделай **Fork** репозитория и работай в нём.

## Модель «4 вопроса»

Любой фронтенд-подход можно разобрать, ответив на четыре вопроса. Задавай их к каждой версии:

1. **Где живут данные?** (переменная в модуле, объект класса, store, кэш запросов, сервер, база данных)
2. **Как обновляется экран?** (вручную через DOM, перерисовка списка целиком, реактивность, виртуальный DOM, перезапрос с сервера)
3. **Как описывается интерфейс?** (строки HTML, jQuery-цепочки, шаблоны, JSX, декораторы)
4. **Где выполняется код?** (только браузер, браузер + сборщик, сервер + браузер)

| Версия | Где данные | Как обновляется экран | Как описан UI | Где выполняется |
|--------|-----------|----------------------|---------------|-----------------|
| 01 vanilla | массив в модуле | вручную: стёр список → нарисовал заново | `createElement` / строки | браузер |
| 02 jQuery | массив в модуле | вручную, но короче | jQuery-цепочки | браузер |
| 03 OOP | класс `PostStore` | Store шлёт событие → View перерисовывается | методы `render()` | браузер (ES-модули) |
| 04 Vue | `ref` / `reactive` | **автоматически** (реактивность на Proxy) | шаблоны `.vue` | браузер + Vite |
| 05 React | `useState` | автоматически (vDOM, перерендер компонента) | JSX | браузер + Vite |
| 06 React+TS | Zustand + кэш TanStack Query | автоматически + инвалидация кэша | JSX + типы | браузер + Vite |
| 07 Next.js | память **сервера** | Server Action → `revalidatePath` → сервер присылает новый UI | JSX (серверные + клиентские компоненты) | **сервер + браузер** |
| 08 Prisma | **PostgreSQL** | как в 07 | как в 07 | сервер + браузер + БД |
| 09 Auth.js | PostgreSQL + сессия пользователя | как в 07 + `useOptimistic` | как в 07 | сервер + браузер + БД + Google |

Главный перелом — между **06 и 07**: данные переезжают из браузера на сервер. До этого «бэкенд» был заглушкой, после — настоящий.

## Важные моменты

- **Каждая папка независима.** `node_modules` ставятся отдельно в каждую (≈ 100–400 МБ на папку). Закончил с версией — можно удалить её `node_modules`.
- **Порты:** Vite — `5173`, Next.js — `3000`, Angular — `4200`. Если порт занят, Vite/Next сами возьмут следующий — смотри адрес в терминале.
- **Версии 8–9 требуют PostgreSQL.** Проще всего через Docker:
  ```bash
  docker run -d --name pg -p 5432:5432 -e POSTGRES_PASSWORD=postgres postgres:16
  ```
  Затем в папке версии: `cp .env.example .env` → поправь `DATABASE_URL` → `npm install` → `npm run db:migrate` → `npm run dev`. Посмотреть таблицы глазами: `npm run db:studio`.
- **Файл `.env` никогда не коммитится** — в нём пароли и секреты. В репозитории лежит только `.env.example` как образец.
- **v09: демо-вход** (`AUTH_DEMO_LOGIN=true`) пускает кого угодно под любым именем — это только для учёбы, чтобы не настраивать Google сразу. Настоящий вход через Google описан в [`09-nextauth/README.md`](09-nextauth/README.md).
- **`next` закреплён на `~15.3.9`** в версиях 7–9. В Next.js 15.5 есть баг: после Server Action с `revalidatePath` кнопка может навсегда остаться в состоянии «загрузка». Не обновляй `next` без проверки.
- **Старые версии API — намеренно.** В `05a` используются `ReactDOM.render` и `createStore` из Redux 4, в `04a` — Vue 2. Это не ошибка: так выглядит код, который встречается в реальных старых проектах. В новых проектах так не пишут.
- **Версии `05a`/`05b` на React 18**, остальные React-версии — на React 19.

## Частые проблемы

| Симптом | Причина и решение |
|---------|------------------|
| Пустая страница в v3/v3a, в консоли ошибка CORS | Открыт через `file://`. Используй Live Server или `npx serve .` |
| `vite: command not found` / `next: not found` | Не выполнен `npm install` в этой папке |
| `Can't reach database server` (v8/v9) | PostgreSQL не запущен или неверный `DATABASE_URL` в `.env` |
| `MissingSecret` (v9) | Не задан `AUTH_SECRET` в `.env` → `npx auth secret` |
| Ошибки установки в Angular | Слишком старый Node — нужен ≥ 20.19 (лучше 22 LTS) |
